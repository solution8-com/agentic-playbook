How to run a wave

  1. One agent per tile, one branch/worktree each. The repo shares a single checkout across environments, so isolate parallel work in a git worktree before branching.
  2. Open draft PRs early so in-flight work is visible; the whole batch merges to main via PR (trunk-only ruleset).
  3. Respect the "coordinate" notes. On append-only files (schema, i18n, routes) let the owner land first, then rebase the rest - conflicts are only on trailing lines.
  4. Run the gates before each PR: npm run lint · test · tsc · build at root and in functions/.
  5. Merge the whole wave, then start the next. Waves are ordered so each one's blockers are green before it begins.
